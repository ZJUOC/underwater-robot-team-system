# 水下机器人团队成员画像与协作管理系统

一个同时服务纳新与社团成员成长的管理系统。当前主线是 `候选人三人组队 -> 一周水下机器人调研 -> 团队材料与个人贡献 -> AI 辅助分析 -> 人工逐人决策`，每条分析依据都能回到具体文件和原文位置。

当前仓库实现面试小组作业 MVP，并保留纳新个人档案、正式成员中心、面试、结构化逐字稿、带 OCR 的资料分析助手、动态画像与证据审核。面试小组作业是登录后的主入口。

## 目录

```text
apps/web        Next.js 管理端
apps/api        FastAPI 服务、SQLAlchemy 模型与 Mock Provider
docs            架构、ER 设计和开发拆分
data            私有数据放置说明；真实问卷只在本地保留
docker          容器部署说明
```

## 本地运行

### 1. API

```bash
cd apps/api
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
alembic upgrade head
uvicorn app.main:app --reload --port 8000
```

API 文档位于 `http://localhost:8000/docs`。本地存在私有 `seed_questionnaire.json` 时，首次启动会导入真实问卷；仓库默认使用不含个人信息的合成演示数据。重复提交和缺失身份的数据不会丢弃，而会保留在对应档案的原始资料中并标记待复核。系统另写入“张三”演示档案及其 Mock 面试数据。

本地演示账号：`admin` / `robot2026`。生产环境必须更换账号、密码与 `AUTH_SECRET`。

### 2. Web

```bash
cd apps/web
npm install
cp .env.example .env.local
npm run dev
```

打开 `http://localhost:3000`。默认 API 地址为 `http://localhost:8000`。

## Docker Compose

```bash
docker compose up --build
```

容器环境使用 PostgreSQL；本地直接运行 API 时默认使用 SQLite，方便快速体验。

## 面试小组作业验收路径

1. 进入“面试小组作业”，新建一项 7 天的“水下机器人一周调研”任务。
2. 从报名者中准确选择 3 人创建小队；同一任务内，一名候选人不能重复分组。
3. 打开小队，上传团队报告、系统结构图、来源清单或过程记录，并分别填写三人的实际贡献、关键结论、困难和来源验证方式。
4. 三份个人说明和至少一份团队报告齐全后提交，再运行分析。团队成果按 40 分评价，个人贡献按 60 分评价；AI 引用必须逐字存在于解析后的原文片段。
5. 审核人逐人核对材料、补充人工评分和追问，提交复核后再确认最终结论。系统不会按小队整体录取或淘汰。
6. 导出小队 CSV，检查团队分、个人分、AI 建议、人工结论和理由是否完整。

## 既有功能验收路径

1. 进入“纳新档案”，搜索并打开任一报名者，检查报名、面试、AI 资料分析与证据是否都关联到同一人。
2. 点击“资料分析助手”，上传 XLSX/XLS、CSV、PDF、DOCX、PPTX、TXT、Markdown、JSON 或图片，并选择要关联的纳新档案。系统优先读取 PDF 文本层，对扫描页、照片、截图和多页 TIFF 自动执行 OCR；结果会显示每个文件的读取方式、页数、OCR 页数、字符数、置信度和异常提示。
3. 进入“面试管理”，直接从纳新档案选择候选人，不需要重新导入名单。
4. 打开 Mock 面试，检查候选人、面试官与问题的逐字稿映射，然后执行“分析面试”。
5. 回到该候选人的纳新档案查看新 Evidence 与画像更新。
6. 在“证据审核”接受或拒绝 AI 证据，原始证据始终保留。
7. 进入“成员中心”，确认这里仅展示已经加入社团的正式成员。

也可以从“面试管理”新建场次，添加问题、录入 Utterance，并人工修正 Speaker 映射。

## 人格标签方法

人格标签采用 Big Five 行为维度的团队协作化表达：探索开放、行动落实、主动表达、协作共情和压力稳定。开发版引擎只从报名动机、相关经历和候选人面试表达中识别明确语言信号，输出信号强度、可信度和原文依据；材料不足时显示“待分析”，不会自动补齐标签。

这些信号不是常模百分位或心理诊断。人格标签只用于帮助面试官理解沟通与协作方式，不得单独用于筛选、排序或决定录取。技术兴趣仍作为独立的原始报名字段保存。

## 安全说明

- 原始问卷包含手机号与 IP；列表不展示敏感字段，详情页对手机号脱敏，原始提交仅通过已认证接口读取。
- 录音、AI 分析前保留三个独立同意字段。
- Evidence 审核使用状态变更，不执行物理删除。
- 上传资料单文件最大 15 MB、资料包最大 40 MB；PDF 最多解析前 25 页，多页图片最多解析前 10 页。通用资料分析助手只保存结构化读取结果；面试小组作业材料会保存到 `MATERIAL_STORAGE_DIR` 指定的私有目录，并且只通过已认证接口下载。
- 生产环境应替换默认密钥、启用对象存储私有桶、部署数据库备份和访问审计。

## 资料读取与 OCR

资料分析采用“原生结构优先、OCR 兜底”的混合策略：文本、JSON、Office Open XML 与 XLS 直接读取结构；PDF 逐页检查文本层，文字不足的页面以 180 DPI 渲染后交给 RapidOCR；常见图片与多页 TIFF 直接识别。OCR 使用 ONNX Runtime 在 API 服务本地运行，不把候选人材料发送给第三方识别服务。

OCR 结果属于机器识别内容，页面会单独显示置信度与读取警告。分析结果保持“待确认”状态，不会自动覆盖个人档案，也不能代替人工核对原材料。
